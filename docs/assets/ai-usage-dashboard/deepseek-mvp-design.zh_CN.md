# AI 使用量仪表盘：DeepSeek MVP 设计

> **状态：** 设计讨论草案，尚未批准实现。讨论记录日期：2026-10-02。

## 1. 目的与范围

本文记录 AI Passport 个人余额仪表盘的首版设计，区分已确认需求、建议和
待决定事项。它不是视觉设计、固件规格、工作量估算，也不表示功能已实现。

MVP **只显示 DeepSeek 账户余额**。所有者接受在设备上输入并保存
DeepSeek API Key。首选的设置方式是手机连接 Passport 临时 Wi-Fi 热点，
再用普通浏览器配置路由器 Wi-Fi；不倾向专用手机应用。Passport 使用电池
供电，屏幕通常关闭，按功能键后查看。亮度和屏幕关闭超时应可由用户调整，
不必重新烧录固件。

本文不授权固件开发，也不代表要修改源码、配置、分区或设备。

### MVP 不包含

- 余额或使用历史、图表以及剩余 Token 估算。
- 其他 AI 服务商、订阅或 Coding Plan 支持。
- OTA、必需后端、配套手机应用，以及刷新频率、API 费用或数据新鲜度保证。

## 2. 已确认需求与建议

### 讨论中已确认

- AI Passport 个人余额仪表盘；首个服务商为 DeepSeek，首版只显示余额。
- 所有者接受在 Passport 上保存 API Key。
- 若可行，优先用手机普通浏览器设置 Wi-Fi；不需要专用应用。
- 电池供电、屏幕通常关闭、按功能键查看，以及无需重新烧录即可调整亮度
  和屏幕关闭超时。
- 用户确认当前安装的第三方固件中有一个由应用作者添加的第八个返回应用入口。
  这只是当前安装的行为，不是通用系统设置。

### 建议方案，尚未确认为产品决策

- **建议设备直接通过 HTTPS 访问 DeepSeek。** 显示文档化的余额响应不需要
  必需后端，且所有者接受设备保存 Key。以后可考虑后端，但后端不会让未文档化的
  账户历史或使用统计 API 变得可用。另行收集的观测记录，或用户提供的官方导出文件
  （如有），属于不同的数据来源，不在本 MVP 范围内。
- Wi-Fi 设置采用有时限、受密码保护的 SoftAP 会话；连接成功或超时后停止
  Web 服务。
- 网络服务独立于仪表盘屏幕生命周期。

## 3. API 与数据含义

DeepSeek 文档定义的请求：

```text
GET https://api.deepseek.com/user/balance
Authorization: Bearer <API_KEY>
```

公开响应包含 `is_available` 和 `balance_infos` 列表，其中每项有
`currency`（`CNY` 或 `USD`）以及字符串字段 `total_balance`、
`granted_balance`、`topped_up_balance`。

- `total_balance` 是该币种当前的总额。
- `granted_balance` 是当前剩余的赠送余额部分。
- `topped_up_balance` 是**当前剩余的充值余额部分**，不是历史累计充值额。
- 这些是货币小数。解析和格式化时避免二进制浮点舍入；CNY 与 USD 分开
  显示，不能相加。
- `is_available` 表示余额是否足够用于 API 调用，不是 Wi-Fi 状态，也不是
  精确的剩余 Token 数量。

限定范围内的文档检查找到受支持的余额 API，但未找到文档化的历史或使用统计
接口。使用公开 API，不读取私有控制台页面或浏览器 Cookie，也不为估算消耗
而调用模型。本文不声称官方轮询限制、接口价格或数据新鲜度保证。普通 Key
没有文档说明的只读权限范围：只查询余额不会限制此 Key 在其他地方可授权的
操作。

## 4. 建议流程与运行方式

### 4.1 Wi-Fi 配置

1. 尚无已保存的 Wi-Fi 凭据（首次设置）时，或用户通过实体按键主动进入配置时，
   启动名称唯一、受 WPA2 密码保护的临时热点。
2. 在设备上显示 SSID、一次性密码和本地网页地址；屏幕不得显示完整 API Key。
3. 用户连接热点，并在普通浏览器中手动打开本地地址。可将 captive portal
   弹窗作为便利功能，但不可依赖它：手机不保证弹窗，设计也不拦截 HTTPS。
4. 说明配置热点没有互联网连接。手机可能显示警告或询问是否保持连接。
5. 在不同字段中收集路由器凭据和 DeepSeek API Key。限制并校验字段，遮蔽秘密值；
   凭据不得出现在 URL、日志或回复中。
6. 使用新的 Wi-Fi 凭据连接目标 2.4 GHz 网络并确认获取 IP 地址。成功后才保存
   新的 Wi-Fi 凭据；失败时保留原有可用凭据。
7. 成功或超时后停止 AP、HTTP 和 DNS 服务，并清理相关任务及事件处理器。

配置热点只提供本地设置，不提供互联网；不需要 NAT/路由器功能。不要假定一部
手机可以同时提供热点并连接设备的配置 AP。用户可能需要预先配置网络、使用
第二台客户端，或在配置后切换手机热点；支持方式需决定并测试。临时离线或已保存
的热点暂时不可达时，不应自动启动配置热点；应保留已保存的 Wi-Fi 设置。重试策略
仍待决定。

### 4.2 余额与屏幕

加入已保存的路由器后，通过认证 HTTPS 调用文档化接口。网络服务独立于屏幕
创建/销毁。HTTP、存储和重试放在工作任务中；按键回调不得阻塞。LVGL 任务
之外访问 LVGL 时持有 `bsp_lvgl_lock()`。删除屏幕之前停止可能访问屏幕的
工作任务、定时器和事件处理器。

按功能键后唤醒显示，并立即呈现最近已知状态；之后可后台刷新。离线缓存值须
标为过期。首次按键是只唤醒屏幕，还是也执行常规按键动作，仍待决定。

按币种分别显示总额、赠送余额和剩余充值余额；具体紧凑布局尚未决定。仅在
时钟可信时显示最近成功时间，否则如实显示未知/相对状态。区分连接、刷新、
过期和错误状态。只有电量计读数有效时才显示电量，否则标记不可用或省略。
提供手动刷新，并可考虑保守的低频轮询。刷新间隔和重试策略待定，本文不暗示
官方 API 频率限制。

## 5. 设置与持久化

亮度和闲置屏幕关闭超时的调整应立即生效，并在正常重启后保留，无需重新烧录。
小型存储也可保存 Wi-Fi 凭据、API Key 和明确选定的偏好。设置可以在设备上、
浏览器页面上或两者兼有；其位置、页面和按键映射都未决定，本文不是完成的 UI
设计。

亮度/超时范围和默认值待定。50% 亮度和 30 秒只是例子，不是选定默认值；实现
时要按商定范围校验。恢复默认值必须经过明确确认，且只清除本应用设置，不得
影响其他设备数据。固件更新或擦除可能影响保存的数据；不保证能从当前应用迁移。
最近余额是在重启后保留，还是只保存在 RAM 中，仍待决定；不要假定每次刷新都
写入 NVS。

所有者表示当前应用习惯用长按 OK 进入设置。这只是待确认的候选操作，不证明
基线固件已有通用设置功能，也不规定仪表盘必须采用该手势。

## 6. 硬件与复用边界

产品规格列出 ESP32-C3、8 MB Flash、无 PSRAM、240 x 320 屏幕、520 mAh 电池
与 CW2017 电量计、2.4 GHz Wi-Fi，以及 GPIO0 ADC 电阻梯形电路上的 UP/DOWN/OK
按键。这些事实提示要关注内存、无线电活动和亮屏时间，但不能据此推算堆预算
或续航时间。

基线 `main` 打开标题为 `FoloToy` 的页面，带有吉祥物和七个硬件测试入口：
Display、Button、Audio、Battery、Wi-Fi、BLE 和 Low Power。用户确认当前安装的
第三方固件中有一个由应用作者添加的第八个返回应用入口。这只是当前安装的行为；
不要假设有通用设置系统，也不要推断具体镜像来源或基线提交。基线 Wi-Fi 演示只在
RAM 中扫描网络，不负责连接或配网。显示演示提供
100%、50%、10% 亮度，退出时恢复 100%；它不保存偏好，也没有闲置超时。

衍生应用必须自行实现 UI，不得复用基线测试菜单、演示页面或视觉外壳；可以
复用 BSP API 和非视觉逻辑。`bsp_display_backlight(0)` 只关闭背光，不代表
整个显示器休眠。低功耗演示只测试定时器 light/deep sleep，不测试 deep sleep
中的按键唤醒。该功能需 BSP 工作和板上验证。

首版可先评估关闭背光、应用继续运行并扫描按键的方案。Wi-Fi 省电也只是候选。
自动 light sleep 是可选实验，不是保证。完成唤醒电路、重连、能耗和体验测试前，
不承诺 deep sleep 或精确续航目标。

## 7. 安全与故障

API Key 是可能授权付费请求的 bearer 凭据。应说明设备丢失后的撤销方法；为设备
单独创建 Key 是合理预防措施。文档、示例、URL、日志中不得包含真实 Key、Wi-Fi
密码或个人数据。NVS 存储不自动加密，也不是安全保险库。Flash/NVS 加密和
Secure Boot 需另行规划；本文不会启用它们。默认分区保持不变。

使用 HTTPS 并校验证书链、主机名和可信的当前日期；不可因时钟错误跳过证书检查。
ESP-IDF 5.5.3 默认关闭 `MBEDTLS_HAVE_TIME_DATE`，因此证书日期校验以及可信
时间（例如请求前通过 SNTP 获取）需要未来显式配置和测试。限制响应字节数和
JSON 大小，设置有限超时、逐步延长重试间隔、限制刷新频率；重定向策略须明确
且安全。

区分热点/浏览器、Wi-Fi 认证/IP、DNS/时间/TLS、HTTP 授权、响应格式以及服务商/
网络临时故障。DeepSeek 授权错误或服务不可用不应使已成功的 Wi-Fi 连接失效，也
不应回滚有效的 Wi-Fi 凭据。显示离线余额缓存
时标记过期，并在已知时保留真实的最近成功时间。配置页也须限制请求和字段、
不回显凭据、拒绝错误输入并完整清理服务。WPA2 不代表 NVS 已加密，本地 HTTP
也不是端到端加密。

## 8. 实施前待决定

1. 确认设备直连服务商（建议方案），或说明可选后端的具体职责和理由。
2. 选择 UI 语言和字体。默认 Montserrat 缺少中文字形；中文 UI 需检查字形/字体
   并验证设备实际显示。
3. 商定亮度/超时范围和默认值，以及保守的轮询和重试策略。
4. 决定设备端或浏览器端设置、首次按键唤醒行为，以及是否采用长按 OK。
5. 决定最近余额是否跨重启保存，以及如何标记和替换过期数据。

长期续航和 deep-sleep 唤醒是未来目标，不能仅凭当前硬件文档作决定。

## 9. 后续验收大纲（尚未执行）

另行获准的实现应测试：主机端响应解析、精确金额格式化、币种隔离、错误、过期
状态转换、输入范围、重试和按键时序；ESP-IDF 构建及合并镜像/分区检查；设备端
浏览器配网、错误密码时保留旧凭据、热点清理、重连、HTTPS 时间/证书、离线缓存、
刷新、按键唤醒、设置持久化和电量读取失败。测量堆、任务栈、无线电/显示功耗及
实际续航后再声明资源指标。确认凭据不会出现在日志或非预期的 UI 输出中。配置期间
可有意显示一次性配置热点密码，但不得显示完整的服务商 API Key 或路由器密码。确认
超大本地请求会安全失败。

本次文档任务状态：Build：NOT RUN；Host tests：NOT RUN；Device tests：NOT RUN。
没有执行设备、账户或 API 请求，也没有检查凭据。
